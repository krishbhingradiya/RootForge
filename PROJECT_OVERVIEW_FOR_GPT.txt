1. EXECUTIVE PROJECT OVERVIEW & VALUE PROPOSITION
================================================================================

WHAT IS ROOTFORGE?
RootForge (AI Solution Builder) is an enterprise-grade digital transformation and 
solution architecture workbench. It is engineered specifically for Management 
Consultants, Principal Solution Architects, Enterprise IT Leaders, and Product 
Strategists.

THE PROBLEM IT SOLVES:
In enterprise consulting and technology architecture engagements, formulating a 
cohesive solution from ambiguous business problems typically takes 4 to 8 weeks 
of manual stakeholder interviews, disparate whiteboard drawings, Excel cost 
estimations, Word SOP documents, and fragmented Visio/Lucidchart diagrams. 
Requirements are frequently lost between business discovery, software 
architecture, UX design, and database schema creation.

THE ROOTFORGE SOLUTION:
RootForge unifies the entire consulting lifecycle into an interconnected, 8-stage 
advisory workbench. An operator or enterprise stakeholder enters a business 
challenge (or uploads internal SOPs/audit PDFs), and the platform guides them 
through an AI-augmented progression:

  [Stage 1: Discovery & Document Ingestion]
         │
         ▼
  [Stage 2: Business Analysis & Digital Maturity]
         │
         ▼
  [Stage 3: Solution Recommendation & Options Comparison (A / B / C)]
         │
         ▼
  [Stage 4: System Architecture & Topology Canvas]
         │
         ▼
  [Stage 5: Target Process Workflow & Decision Gate Modeling]
         │
         ▼
  [Stage 6: UX Wireframe Studio & Hi-Fi Interactive Simulator]
         │
         ▼
  [Stage 7: Database Relational Model (ERD) & REST API Blueprint]
         │
         ▼
  [Stage 8: Implementation Planning, Sprint Roadmap & Cost Estimations]
         │
         ▼
  [Governance: Cross-stage Approvals, Version Snapshots & Multi-format Export]

CORE PHILOSOPHY:
- Advisory & Human-in-the-Loop: RootForge does not treat AI as an unchecked black box. 
  Every stage acts as an advisory baseline that human architects can edit, refine, 
  approve, or snapshot into immutable versions.
- Deterministic Reliability: Out-of-the-box, the system operates on a specialized 
  domain-aware deterministic intelligence engine. Even without external OpenAI or 
  Gemini API keys configured, it generates domain-accurate enterprise artifacts. 
  External LLMs can be seamlessly plugged in via standard environment variables.
- Tri-lingual Enterprise Ready: The entire user interface, navigation, alerts, 
  and core advisory feedback natively support English (en), Hindi (hi), and Gujarati (gu).

3. END-TO-END APPLICATION FLOW & USER JOURNEY (STAGE-BY-STAGE)
================================================================================

Here is the exact operational flow of how a user interacts with RootForge:

STEP 1: LANDING & AUTHENTICATION
  - User visits "/" (Landing Page).
  - Can test an interactive challenge in the hero section ("Our customer support team 
    spends too much time manually classifying requests...").
  - User clicks "Explore Live Demo" or logs in at "/login" using pre-seeded credentials 
    or custom registration.
  - JWT token and user profile are persisted to `localStorage` (`aisb_token`, `aisb_user`).

STEP 2: WORKSPACE SELECTION OR CREATION
  - User enters "/app/workspaces" (Workspace List Page).
  - Displays all existing workspaces with their industry badge, status, and artifact counts.
  - User can click "Create Workspace" modal (entering Name, Objective, Challenge, Industry, 
    Target Users, Expected Outcome) OR click into the pre-seeded "Customer Support Transformation" workspace.

STEP 3: WORKSPACE OVERVIEW DASHBOARD
  - Navigates to "/app/workspaces/:id" (Workspace Overview Page).
  - Displays Executive Header Banner, industry categorization, and current progress.
  - Displays 5 Assessment Scores: Digital Maturity (68%), AI Readiness (84%), Solution 
    Readiness (88%), Architecture Readiness (92%), Implementation Readiness (85%).
  - Shows 8 stage progress cards with status indicators (COMPLETED, NOT_STARTED, IN_PROGRESS).
  - Allows uploading internal enterprise PDF/DOCX files directly.
  - Displays next suggested action ("All stages ready. Review with stakeholders and export complete solution.").

STEP 4: STAGE 1 — DISCOVERY & DOCUMENT INGESTION
  - Route: "/app/workspaces/:id/discovery"
  - User converses with the AI Business Consultant.
  - System dynamically provides context-aware suggested questions (e.g., "What is the 
    current distribution of inbound volume across email, portal, chat, and phone?").
  - User types answers or clicks pre-built prompts.
  - User uploads PDF documents (e.g., standard operating procedures, vendor reports). 
    Backend extracts text using `pdf-parse` and sets status to "ANALYZED".

STEP 5: STAGE 2 — BUSINESS ANALYSIS
  - Route: "/app/workspaces/:id/analysis"
  - User clicks "Synthesize Analysis" (or views seeded analysis).
  - AI synthesizes: Current State, Future State, 5 Strategic Goals, 4 Pain Points, 
    4 Stakeholder Personas, 5 Functional/Technical Requirements, 3 Gaps, and 4 Automation Opportunities.
  - User can enter "Edit Mode" to modify any text field, adjust Digital Maturity score (slider), 
    and save updates to the database.
  - User can submit formal approval sign-off.

STEP 6: STAGE 3 — SOLUTION RECOMMENDATION
  - Route: "/app/workspaces/:id/solution"
  - Formulates 3 comparative strategic alternatives:
      * Option A: Workflow Rules Engine Automation (Fastest, low cost, 35% automation)
      * Option B: AI-Assisted Support Platform (Recommended, balanced ROI, 70% automation)
      * Option C: Full Autonomous Enterprise Overhaul (Transformational, high risk/cost, 90% automation)
  - User selects their preferred strategy (updates `selectedOption` in database).
  - Explores Tech Stack breakdown (React, Express, PostgreSQL/SQLite, Pluggable AI, REST Gateways).
  - Evaluates Implementation Risks and Mitigation strategies.

STEP 7: STAGE 4 — SOLUTION ARCHITECTURE CANVAS
  - Route: "/app/workspaces/:id/architecture"
  - Interactive visual architecture map organized across 6 architectural tiers:
      1. Client Layer (Web App, Mobile Portal)
      2. Gateway Layer (API Gateway & Security Proxy)
      3. Application Services (Core Workflow Engine)
      4. AI & Automation (Pluggable AI Dispatcher)
      5. Persistence Layer (Transactional Relational DB)
      6. Integrations Layer (Legacy ERP / Cloud Webhooks)
  - Interactive nodes display technology badges and network connection lines.
  - User can click any node to view/edit details, or click "+ Add Component" to insert 
    custom services.
  - Tabs provide textual documentation for HLD, LLD, Security, and Integrations.
  - User can snapshot the topology as a new version.

STEP 8: STAGE 5 — PROCESS DESIGNER
  - Route: "/app/workspaces/:id/process"
  - Models business processes across 3 distinct perspectives:
      * Workflow View: Linear sequential step cards with condition badges and step re-ordering.
      * Swimlane View: Categorized by actors (Customer, AI Engine, System Rules, Supervisor, Frontline Operator).
      * Decision Tree View: Highlights conditional routing logic (e.g., "Confidence >= 80%", "Evaluate: High vs Normal Priority").
  - User can add new steps, edit existing steps, or delete steps.

STEP 9: STAGE 6 — UX WIREFRAME STUDIO & LIVE SIMULATOR
  - Route: "/app/workspaces/:id/ux"
  - Viewport Switcher: Desktop (100%), Tablet (768px), Mobile (375px frame with simulated status bar).
  - Mode Switcher: Hi-Fi Interactive UI (simulating the actual built software) vs. Wireframe Blueprint.
  - 6 Design Archetypes: "Modern SaaS", "Enterprise Slate", "Cyber Operations", 
    "Warm Luxury", "Nordic Minimal", "FinTech Violet".
  - Live Interactive Capabilities:
      * Executive Dashboard with simulated KPI metric cards and triage speed charts.
      * Operator Workspace with a live clickable ticket queue (TCK-1049, TCK-1050, etc.).
      * AI Copilot Drawer simulating draft customer response generation with 1-click approval.
      * Live Customer Chatbot simulator where users can type inquiries and receive auto-responses.
      * Live Routing Rule Editor with toggle switches.
      * Interactive ROI & Cost-Savings Calculator with monthly ticket volume slider.

STEP 10: STAGE 7 — DATABASE & API DESIGNER
  - Route: "/app/workspaces/:id/database"
  - Tab 1 (Data Model & ERD): Interactive entity dictionary (User, Customer, Ticket, Department), 
    field data types, primary keys, and foreign key relations.
  - Tab 2 (SQL DDL): Formatted SQL schema ready to execute in PostgreSQL or SQLite.
  - Tab 3 (Prisma Schema): Formatted Prisma schema ready to drop into backend codebases.

STEP 11: STAGE 8 — IMPLEMENTATION PLANNER

  - 12-week Agile Roadmap broken down into 5 phases:
      Phase 1: Discovery & Architecture Alignment (2 Weeks)

      Phase 3: AI Intelligence & Copilot Workspace (3 Weeks)
      Phase 4: Integration & End-to-End Validation (2 Weeks)
      Phase 5: Staged Rollout & Operational Handoff (2 Weeks)
  - Toggle between Gantt-style Timeline view and tabular Task List view.
  - Interactive status toggles for tasks (TODO, IN_PROGRESS, COMPLETED).
  - Ability to add new tasks assigned to specific roles (Architect, BA, Backend Dev, QA).

STEP 12: COLLABORATION, AUDIT TRAIL & REVISION HISTORY

STEP 13: EXPORT CENTER & DELIVERABLE GENERATION

      2. Executive Printable Report (.html): Styled dossier with print styles, opening in

      3. Complete Architecture JSON (.json): Complete serialized workspace bundle for machine parsing.
      4. Sprint Task Spreadsheet (.csv): Implementation tasks formatted for Jira/Excel import.

4. FULL TECHNICAL STACK & ARCHITECTURE
================================================================================

FRONTEND:
  - Framework: React 18.3.1 (SPA) built with Vite 6.0.1
  - Routing: React Router DOM 6.28.0 (Nested layouts, ProtectedRoute, AdminRoute)
  - Styling System: Pure Vanilla CSS with CSS Custom Properties (Design Tokens) in `index.css`.
    * No Tailwind CSS bloat. Clean semantic token architecture:
      --bg-canvas, --bg-surface, --text-primary, --accent-amber, --accent-green, --border-subtle.
    * Full responsive grid and flexbox utility structure.
  - Iconography: Lucide React (over 40 contextual icons utilized)
  - Animation & Polish: Framer Motion + Canvas Confetti (for approvals and milestones)
  - State Architecture: Lightweight React Context API:
      * AuthContext.jsx: User session, login, register, demo login, logout.
      * WorkspaceContext.jsx: Current active workspace, stage status, global selector.
      * LanguageContext.jsx: Trilingual localization state with 124KB dictionary (`translations.js`).
      * ThemeContext.jsx: Dark Mode / Light Mode toggle with `html[data-theme]` attributes.
  - API Client: Centralized wrapper in `frontend/src/services/api.js` handling Bearer JWT 
    headers, multipart FormData for file uploads, and 401 token refresh redirects.

BACKEND:
  - Runtime: Node.js (ES Modules, `"type": "module"`)
  - Server Framework: Express 4.21.1
  - Database ORM: Prisma ORM 5.22.0
  - Database Engine: SQLite (`backend/prisma/dev.db`) in local development; fully compatible 
    with PostgreSQL for production deployment via `DATABASE_URL`.
  - Security & Auth:
      * Bcryptjs (10 salt rounds) for password hashing.
      * JsonWebToken (JWT) with Bearer token authentication middleware (`auth.js`).
      * Role-Based Access Control (`requireRole('ADMIN')`, `requireRole(['CONSULTANT', 'ADMIN'])`).
      * CORS enabled for frontend Vite dev server (`http://localhost:5175`).
  - File Uploads & Document Ingestion:
      * Multer for file handling (`uploads/` directory).
      * `pdf-parse` for automated extraction of raw text from uploaded PDF documents.

AI & INTELLIGENCE ARCHITECTURE:
  - Location: `backend/src/ai/`
  - Dual-Mode Provider Abstraction:
      1. Deterministic Demo Provider (`backend/src/ai/providers/demoProvider.js` - 45KB):
         * Detects domain themes (Customer Support, Supply Chain, FinTech/Claims, Healthcare, HR Operations).
         * Generates comprehensive, contextual discovery questions, business analyses, 
           options comparisons, architecture nodes, process steps, wireframe schemas, 
           and sprint tasks dynamically based on workspace name, objective, challenge, 
           and uploaded documents.
      2. External Provider Adapter (`backend/src/ai/providers/externalProvider.js`):
         * OpenAI / Gemini / Anthropic compatible HTTP adapter.
         * Activates automatically if `AI_PROVIDER` is set and `AI_API_KEY` is provided in `.env`.

6. REAL IMPLEMENTATIONS VS. SIMULATED / MOCKED COMPONENTS
================================================================================

To ensure total clarity for developers and LLMs, here is the exact boundary between 
what is fully operational and what is simulated:

WHAT IS FULLY REAL & OPERATIONAL:
  ✓ Real Express REST API backend running on Node.js (Port 5005).
  ✓ Real SQLite relational database via Prisma ORM (`backend/prisma/dev.db`).
  ✓ Real JWT authentication, token decoding, and bcrypt password verification.
  ✓ Real file system uploads (Multer) and real PDF text extraction (`pdf-parse`).
  ✓ Real database persistence for all created/updated workspaces, analyses, solutions, 
    architecture nodes, process steps, tasks, comments, approvals, and versions.
  ✓ Real file downloads generated dynamically on the fly (Markdown, JSON, CSV).
  ✓ Real trilingual internationalization switching on-the-fly (English, Hindi, Gujarati).
  ✓ Real CSS dark mode and light mode switching.

WHAT IS SIMULATED / MOCKED / HEURISTIC:
  ~ Default AI Generation Engine: Uses `demoProvider.js` (deterministic rules and 
    domain-tailored templates) unless the user adds an `AI_API_KEY` in `.env` or Settings.
  ~ Third-Party Enterprise Systems: In the Customer Support workspace, integrations 
    with "Shopify ERP", "Zendesk", and "Salesforce" are modeled as architectural 
    blueprints and UI simulator mockups; there is no live outbound HTTP call to a real Shopify store.
  ~ Real-Time Collaboration: Comments, approvals, and activity logs update on page 
    load and user submission via REST. There is no WebSocket / Socket.io server.
  ~ PDF Generation: Instead of compiling PDFs via heavy server-side headless browsers 
    (Puppeteer), RootForge generates a standalone, styled HTML document that utilizes 
    standard browser print stylesheets (`@media print`) for 1-click PDF printing.
